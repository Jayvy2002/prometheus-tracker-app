📊 QU'EST-CE QUE PROMETHEUS ?
───────────────────────────────────────────────────────────────────────────────
Prometheus est une application complète de suivi fitness : tu logs tes séances
d'entraînement, tes repas, ton poids, et vois des statistiques. C'est comme un
coach et nutritionniste dans ta poche.

• Statut : Actuellement en production live (tracker.prometheus-fit.com)
• Plateforme : Web + PWA (peut être installée comme app sur téléphone)
• Langues : English + French
• Paiements : Premium via Stripe (€9.99/mois ou €99/an)


✅ CE QUI MARCHE BIEN (Les Forces de l'App)
───────────────────────────────────────────────────────────────────────────────

1. Architecture Propre & Organisée
   → Le code est bien rangé : chaque feature (workout, nutrition, etc.) a sa
     propre section. Facile de rajouter des features.

2. Sécurité de Base OK
   → Les données utilisateur sont bien protégées : chaque user ne peut voir
     que SES propres données. Impossible qu'un user A vole les données du
     user B. ✅

3. Zéro Bugs de Sécurité XSS/Injection
   → Pas de risques d'injection de code malveillant. Bonne pratique partout.

4. Fonctionnalités Complètes
   → Workout tracking, nutrition, poids, calendrier, stats, routines, scanner
     code-barres, PWA offline. C'est une app complète.

5. TypeScript Strict
   → Le code est typé (pas de bugs "types fantômes"). Bon pour la stabilité.


🔴 PROBLÈMES IDENTIFIÉS (Audit Complet)
───────────────────────────────────────────────────────────────────────────────

CATÉGORIE A : SÉCURITÉ (Le plus important à corriger)
──────────────────────────────────────────────────────

Problem #1 : CORS Trop Ouvert ⚠️
  Niveau : 🔴 CRITIQUE
  Explication simple : Imagine que ta maison a une porte d'entrée qui dit
    "tout le monde peut entrer". N'importe quel site malveillant peut
    envoyer des requêtes à tes Edge Functions. Même avec une serrure
    (JWT token), la porte ouverte est un problème.
  Impact : Quelqu'un peut spammer des analyses IA ou créer des paiements.
  Temps pour fixer : 5 minutes
  Solution : Restreindre la porte → seulement tracker.prometheus-fit.com peut entrer

Problem #2 : Pas de CSP Headers 🛡️
  Niveau : 🟠 MOYEN
  Explication : CSP = "Content Security Policy". C'est comme une liste
    blanche "voici les sites autorisés à charger du code". Sans elle,
    quelqu'un pourrait injecter du code externe malveillant.
  Impact : Risque XSS si quelqu'un réussit une injection (pas grave actuel
    car pas de XSS detecté, mais bon d'ajouter en prévention).
  Temps pour fixer : 2 minutes
  Solution : Ajouter une ligne dans le HTML avec la liste autorisée

Problem #3 : Pas de Security Headers 🔒
  Niveau : 🟡 BAS
  Explication : Security Headers = instruires au navigateur de bien se
    comporter (no clickjacking, no MIME sniffing, etc.).
  Impact : Faible, surtout si on est sur Netlify (ça gère déjà pas mal).
  Temps pour fixer : 2 minutes
  Solution : Ajouter headers dans netlify.toml

Problem #4 : localStorage Non Chiffré 🔐
  Niveau : 🟡 BAS
  Explication : Les préférences utilisateur (langue, cache) sont stockées
    en texte clair. Si quelqu'un accède à l'ordi, peut les lire.
  Impact : Faible (données non-sensibles), mais bad practice.
  Temps pour fixer : 5 minutes
  Solution : Utiliser sessionStorage (données temporaires) ou chiffrer

Problem #5 : Validation Mot de Passe Faible
  Niveau : 🟡 BAS
  Explication : Actuellement min 6 caractères. Pas de règles (uppercase,
    number, etc.). Facile à brute-force.
  Impact : Faible (Supabase gère, mais mauvaise pratique).
  Temps pour fixer : 10 minutes
  Solution : Enforcer min 8 chars + uppercase + number

CATÉGORIE B : FEATURES MANQUANTES (Impactent Rétention & UX)
──────────────────────────────────────────────────────────────────────────────

Problem #6 : Pas de Notifications/Rappels 📬 (CRITIQUE POUR RÉTENTION)
  Niveau : 🔴 CRITIQUE
  Explication : L'app peut t'envoyer des rappels "N'oublie pas ta séance !"
    via notifications navigateur. JAMAIS implémenté. Résultat : les users
    oublient d'utiliser l'app → churn élevé.
  Impact : Rétention utilisateur très faible. Différence entre 20% et 80%
    retention rate.
  Temps pour fixer : 2-3 heures
  Solution :
    1. Implémenter Web Push API côté client
    2. Créer Edge Function "send-daily-reminders" (existe déjà, pas appelée)
    3. Ajouter UI pour que user choisisse heure rappel

Problem #7 : Image Recognition Produits Incomplet 🍽️
  Niveau : 🔴 CRITIQUE
  Explication : Scanner code-barres marche. Mais 50% des produits n'ont pas
    de code-barres (fruits, viande fraîche, plats faits maison). L'app
    devrait pouvoir identifier produits par PHOTO. Une Edge Function existe
    (GPT-4o Vision) mais pas connectée à l'UI.
  Impact : User ne peut pas logger sans code-barres → frustration.
  Temps pour fixer : 2-3 heures
  Solution :
    1. Ajouter mode "Photo du produit" dans ScannerPage
    2. Envoyer photo à GPT-4o Vision
    3. Récupérer nutrition, ajouter au journal

Problem #8 : Onboarding Rigide (UX Friction)
  Niveau : 🟠 MOYEN
  Explication : Nouveau user = 5 étapes onboarding OBLIGATOIRES avant
    accès app. Peut prendre 10 min. User peut abandonner avant finir.
  Impact : Conversion rate baisse.
  Temps pour fixer : 1-2 heures
  Solution :
    1. Montrer preview des features avant onboarding
    2. Permettre "Skip for now, complete later"
    3. Ajouter progressbar + temps estimé

Problem #9 : Dashboard Peu Engageant pour Nouvel User
  Niveau : 🟠 MOYEN
  Explication : Après onboarding, dashboard est vide (pas de données).
    Peut sembler ennuyeux, pas engageant.
  Impact : Engagement nouvel user faible.
  Temps pour fixer : 1-2 heures
  Solution :
    1. Ajouter widget "Aujourd'hui en bref" (calories restantes, etc.)
    2. Empty states guidés → "Logue ton premier workout ici"
    3. Objectifs visuels

Problem #10 : Nutrition UX Gaps 🍽️
  Niveau : 🟡 BAS
  Explication : Petits gaps UX : pas de "réutilise hier's meal", indicateurs
    visuels progression calories.
  Impact : Faible, mais améliore UX.
  Temps pour fixer : 1-2 heures

⚠️ RISQUES IDENTIFIÉS (À Surveiller)
───────────────────────────────────────────────────────────────────────────────

1. Notifications Spamming
   Risk : User se sent spammé → désactive notifications → rétention down
   Mitigation : User contrôle fréquence (daily, 3x/week, etc.)

2. AI Rate Limiting Abuse
   Risk : User teste "image recognition" 100x → coûts OpenAI explosent
   Mitigation : Limit 10 analyses/day déjà en place ✅

3. CORS Fix Mais Pas Testée
   Risk : Restreindre CORS casse local dev
   Mitigation : Tester avec http://localhost:5173

4. Data Loss sur Health Integrations
   Risk : Sync mal fait → perte données
   Mitigation : Dry-run, logs verbeux, rollback plan
